# Chapter 29: Small Project — Deploying "django-notes-app" End-to-End

This chapter ties everything together: taking a real application from source code all the way to running on Kubernetes, accessible in a browser.

## The full flow
**Source code → Docker image → Push to Docker Hub → Kubernetes pulls it → Namespace + Deployment + Service → Port-forward → Access in browser**

## Commands

### 1. Clone the app's source code
```bash
git clone <repository-url>
cd django-notes-app
git checkout dev
```
- `git clone <url>` → downloads a copy of the project's code repository.
- `cd django-notes-app` → move into the project's folder.
- `git checkout dev` → switches to the `dev` branch, since that's where this particular version of the app's code lives (repos often have multiple branches for different versions/features).

### 2. Build a Docker image from the project's Dockerfile
```bash
docker build -t notes-app-k8s .
```
**What it does:** `docker build` reads the project's `Dockerfile` (a set of instructions for packaging the app) and builds a Docker image from it.
- `-t notes-app-k8s` → **t**ags (names) the resulting image `notes-app-k8s`.
- `.` → tells Docker to look for the Dockerfile in the **current directory**.

### 3. Log in to Docker Hub
```bash
docker login -u <your-dockerhub-username>
```
**What it does:** Logs your terminal into Docker Hub (the public registry where Docker images are stored/shared), using a personal access token as the password (created on Docker Hub's website with read/write/delete permissions) instead of your actual account password — a more secure practice.

### 4. Tag the image with your Docker Hub username
```bash
docker image tag notes-app-k8s:latest <your-dockerhub-username>/notes-app-k8s:latest
```
**What it does:** Docker Hub requires images to be named `<username>/<image-name>:<tag>` so it knows which account's "namespace" the image belongs to. This command renames (tags) your locally-built image to match that format, without rebuilding it.

### 5. Push the image to Docker Hub
```bash
docker push <your-dockerhub-username>/notes-app-k8s:latest
```
**What it does:** Uploads your tagged image to Docker Hub, making it publicly available for anyone (including your Kubernetes cluster) to pull/download. **This step is essential** — Kubernetes can only pull images from a registry it can reach; a purely local image won't work inside the cluster (unless you're using a special local-image-loading trick specific to KIND/Minikube).

### 6. Create a project folder for your Kubernetes YAML files
```bash
mkdir k8s
cd k8s
```

### 7. Write the Namespace manifest
```bash
vim namespace.yaml
```
```yaml
kind: Namespace
apiVersion: v1
metadata:
  name: notes-app
```

### 8. Write the Deployment manifest
```bash
vim deployment.yaml
```
```yaml
kind: Deployment
apiVersion: apps/v1
metadata:
  name: notes-app-deployment
  namespace: notes-app
spec:
  replicas: 1
  selector:
    matchLabels:
      app: notes-app
  template:
    metadata:
      labels:
        app: notes-app
    spec:
      containers:
        - name: notes-app
          image: <your-dockerhub-username>/notes-app-k8s:latest
          ports:
            - containerPort: 8000
```
**Key detail:** `image:` points to the image you just pushed to Docker Hub (not a local path) — this is how Kubernetes knows what to download and run. `containerPort: 8000` because this particular Django app runs on port 8000 (not the usual nginx port 80).

### 9. Write the Service manifest
```bash
vim service.yaml
```
```yaml
kind: Service
apiVersion: v1
metadata:
  name: notes-app-service
  namespace: notes-app
spec:
  selector:
    app: notes-app
  ports:
    - protocol: TCP
      port: 8000
      targetPort: 8000
  type: ClusterIP
```

### 10. Apply everything (in this order — namespace first!)
```bash
kubectl apply -f namespace.yaml
kubectl apply -f deployment.yaml
kubectl apply -f service.yaml
```
**Why namespace first?** Because the Deployment and Service both reference `namespace: notes-app` — if that namespace doesn't exist yet, applying them would fail.

### 11. Check the pod is running
```bash
kubectl get pods -n notes-app
```

### 12. Expose the service to your browser
```bash
kubectl port-forward service/notes-app-service -n notes-app --address 0.0.0.0 8000:8000
```
Then open your EC2 instance's security group, add an inbound rule allowing port `8000`, and visit:
```
http://<ec2-public-ip>:8000
```
You should see the actual Django Notes App running, served entirely through your Kubernetes cluster.

## Key lesson for students
This chapter is the **template you'll reuse for basically any real application**:
1. Build & push a Docker image.
2. Write a Namespace, Deployment, and Service YAML.
3. Apply them in order (namespace → deployment → service).
4. Port-forward + open the firewall to actually view it.

This is the exact recipe you'll repeat again in the bigger projects later in the course (Chat App, .NET/Python 3-tier app, EKS mega project) — just with more moving pieces (databases, Ingress, monitoring, etc.).

| `docker login -u <username>` | Log in to Docker Hub |
