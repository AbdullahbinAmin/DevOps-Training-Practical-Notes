# Chapter 12: Minikube — Installation & Cluster Creation

**What is Minikube?** Another tool (like KIND) to create a small local Kubernetes cluster on a single machine, useful for learning/practice.

## Commands

### 1. Set up a working folder
```bash
mkdir minikube
cd minikube
```
Creates and moves into a folder called `minikube` to keep things organized.

### 2. Install required base tools (prerequisites)
```bash
sudo apt-get update
sudo apt-get install -y curl wget
```
`curl` and `wget` are download tools — needed so the system can fetch the Minikube binary from the internet.

### 3. Enable Docker to auto-start
```bash
sudo systemctl enable docker
```
**What it does:** `systemctl enable` tells Linux "if this server ever restarts, automatically start the Docker service again on boot" — so you don't have to manually start Docker every time.

### 4. Download Minikube
```bash
curl -LO https://storage.googleapis.com/minikube/releases/latest/minikube-linux-amd64
```
Downloads the latest Minikube binary for Linux (amd64 = standard 64-bit processor architecture) and saves it with its original filename (`-O` keeps the remote file's name; `-L` follows redirects).

### 5. Make it executable and move it to the system path
```bash
sudo install minikube-linux-amd64 /usr/local/bin/minikube
```
(or equivalently `chmod +x` then `sudo mv`) — makes the downloaded file runnable and puts it in `/usr/local/bin` so you can just type `minikube` from anywhere.

### 6. Check Minikube installed correctly
```bash
minikube version
```
Prints the installed Minikube version to confirm the install worked.

### 7. Start the Minikube cluster
```bash
minikube start --driver=docker --vm=true
```
- `minikube start` → boots up a Kubernetes cluster.
- `--driver=docker` → tells Minikube to run the cluster **using Docker containers** underneath (instead of a full virtual machine hypervisor).
- `--vm=true` → tells Minikube to treat this as running inside a virtual machine environment. This flag matters specifically **when you're running on an EC2 instance**, since EC2 instances are themselves virtual machines and Minikube needs to know that to configure networking correctly.

This will pull the Kubernetes node image, create the Docker container(s) for the cluster, and set everything up.

### 8. Check nodes (and understand kubectl "context" switching)
```bash
kubectl get nodes
```
**Important lesson here:** kubectl doesn't automatically know which cluster you mean if you have multiple clusters (KIND cluster AND Minikube cluster both existing at once). By default it points to whichever cluster you set up or switched to **most recently**.

To specifically check a particular cluster regardless of current default:
```bash
kubectl get nodes --context kind-tws-cluster
```
`--context` lets you target a **specific** cluster by name, without changing your default.

### 9. Permanently switch your default cluster context
```bash
kubectl config use-context kind-tws-cluster
```
**What it does:** `kubectl config use-context <name>` changes which cluster kubectl talks to **by default** from now on (until you switch again), so you don't need to repeat `--context` every time.

### 10. Delete the Minikube cluster (cleanup)
```bash
minikube delete
```
**What it does:** Completely deletes/tears down the Minikube cluster. After this, running `kubectl get nodes` (if it's still pointed at Minikube) will show a **"can't find the server"** error, because that cluster no longer exists.

## Key lesson for students
- You can have **multiple Kubernetes clusters** installed at once (KIND, Minikube, EKS, etc.) on the same machine.
- `kubectl` uses something called a **context** to know which cluster to talk to.
- Use `--context <name>` to target one cluster temporarily, or `kubectl config use-context <name>` to switch your default permanently.
