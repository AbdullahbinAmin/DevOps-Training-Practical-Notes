# Chapter 15: Pods

**What is a Pod?** The smallest deployable unit in Kubernetes. A Pod is a wrapper around one (or more) containers. Even though you're really running a Docker container, Kubernetes always runs it *inside* a Pod, never the container directly.

## Writing a Pod manifest (pod.yaml)

```bash
vim pod.yaml
```
Example content:
```yaml
kind: Pod
apiVersion: v1
metadata:
  name: nginx-pod
  namespace: nginx
spec:
  containers:
    - name: nginx
      image: nginx:latest
      ports:
        - containerPort: 80
```
**Explanation:**
- `kind: Pod` → this file describes a Pod.
- `apiVersion: v1` → core/basic Kubernetes API version.
- `metadata.name` → the pod's name (`nginx-pod`).
- `metadata.namespace` → which namespace this pod belongs to (`nginx` here — must already exist).
- `spec.containers` → a **list** of containers to run inside this pod (a pod can have more than one container).
  - `name` → name of this container.
  - `image` → which Docker image to use (`nginx:latest` = the newest official nginx image from Docker Hub).
  - `ports.containerPort` → which port the container listens on internally (nginx normally uses port 80).

**Tip:** If you don't know the exact YAML structure, you can always Google **"pods kubernetes"** and look at the official Kubernetes documentation, which gives the exact template/spec to copy from.

## Commands

### 1. Apply the pod manifest
```bash
kubectl apply -f pod.yaml
```
Creates the pod as described in the file.

### 2. Check if it's running (remember the namespace!)
```bash
kubectl get pods -n nginx
```
**Common beginner mistake:** if you just run `kubectl get pods` without `-n nginx`, it looks in `default` and shows nothing — because your pod's YAML said its namespace is `nginx`, not `default`.

### 3. Go INSIDE a running pod (like `docker exec`)
```bash
kubectl exec -it nginx-pod -n nginx -- bash
```
**What it does:**
- `exec` → execute a command inside a running container.
- `-it` → combines two flags: `-i` (interactive, keep input open) and `-t` (allocate a terminal), so you get a proper interactive shell session — the exact same idea as `docker exec -it`.
- `nginx-pod` → the name of the pod you want to enter.
- `-n nginx` → which namespace it's in.
- `-- bash` → the command to run inside the container once you're in (`bash` starts an interactive shell). The `--` separates kubectl's own flags from the command you want to run inside the container.

Once inside, you can run normal Linux commands, e.g.:
```bash
ls
curl 127.0.0.1
```
`curl 127.0.0.1` tests the nginx server from inside its own pod — you should see nginx's default **"Welcome to nginx!"** HTML page returned, confirming the container is actually serving web traffic correctly.

### 4. Describe a pod (very important for debugging!)
```bash
kubectl describe pod nginx-pod -n nginx
```
**What it does:** Shows **everything** about the pod's history and current state:
- Its name, namespace, priority, service account.
- Which **node** it's running on.
- Start time, IP address, container ID, image used, current state (Running/Pending/CrashLoopBackOff, etc.).
- Volume mounts.
- A full **Events** log at the bottom showing the step-by-step story: *scheduled → image pulled → container started* — this tells you exactly what happened (and where it failed, if it failed).

**Why this matters:** This is your #1 debugging tool. If a pod isn't working, `describe` is almost always the first command to run to understand why.

## The full request flow (good to understand, not a command, but important theory)
1. You run `kubectl apply -f pod.yaml`.
2. **kubectl** sends this request to the **API server**.
3. The **API server** asks the **scheduler** to decide which node this pod should run on.
4. The **scheduler** picks a node and reports back.
5. The **kubelet** on that node pulls the required image and starts the container.
6. The kubelet reports the pod's status back to the API server, which stores it in **etcd** (the cluster's database) — this is exactly what `kubectl describe` is reading and showing you.

## Key commands to remember from this chapter

| Command | Purpose |
|---|---|
| `kubectl apply -f pod.yaml` | Create/update a pod from a YAML file |
| `kubectl get pods -n <namespace>` | Check if the pod is running |
| `kubectl exec -it <pod> -n <namespace> -- bash` | Go inside a running pod's container |
| `kubectl describe pod <pod> -n <namespace>` | Full debugging details about a pod |
