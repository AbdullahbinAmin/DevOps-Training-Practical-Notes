# Chapters 9–11: Installing KIND, kubectl, Docker & Creating a KIND Cluster

## What is KIND?
**KIND = Kubernetes IN Docker.** It lets you run a full Kubernetes cluster using Docker containers as "fake nodes" — great for practicing on a single machine (laptop or one EC2 server) without paying for multiple servers.

---

## Part A: Installing KIND, kubectl, and Docker (on the EC2 Ubuntu server)

### 1. Create and open an install script
```bash
vim install_kind.sh
```
**What it does:** Opens the `vim` text editor to create a new file named `install_kind.sh`. This file will be a **shell script** — a text file full of commands that run one after another when executed.

Inside the script, the important lines are:

```bash
#!/bin/bash
curl -Lo ./kind "https://kind.sigs.k8s.io/dl/v0.25.0/kind-linux-amd64"
chmod +x ./kind
sudo mv ./kind /usr/local/bin/kind
```
- `#!/bin/bash` → tells Linux "run this file using the bash shell."
- `curl -Lo ./kind <url>` → downloads the KIND program from its official download URL and saves it locally as a file named `kind`. (`-L` follows redirects, `-o` saves the output to a file.)
- `chmod +x ./kind` → makes the downloaded `kind` file **executable** (runnable as a program), same idea as the `chmod 400` earlier but this time granting "execute" permission instead.
- `sudo mv ./kind /usr/local/bin/kind` → moves the `kind` program into a system folder (`/usr/local/bin`) so you can type `kind` from **anywhere** in the terminal, not just this folder.

### 2. Give the script permission to run and execute it
```bash
chmod 777 install_kind.sh
./install_kind.sh
```
- `chmod 777` → gives everyone (owner, group, others) full read/write/execute permission on the script — quick and easy for a practice environment (not something you'd normally do on a production server).
- `./install_kind.sh` → runs the script (the `./` means "look in the current folder for this file").

### 3. Install Docker
```bash
sudo apt-get update
```
**What it does:** Refreshes the list of software packages Ubuntu knows about, so it knows the latest available versions before installing anything.

```bash
sudo apt-get install docker.io
```
**What it does:** Installs Docker itself on the server.

### 4. Check Docker is working
```bash
docker ps
```
**What it does:** Lists all currently running Docker containers. If Docker isn't set up correctly you'll get a **"permission denied"** error here.

### 5. Fix Docker's "permission denied" error
```bash
whoami
```
**What it does:** Prints your currently logged-in username (so you know exactly which user needs permission).

```bash
sudo usermod -aG docker $USER
```
**What it does:** Adds your current user (`$USER` is an environment variable holding your username) to the special **`docker` group**. Only users in this group are allowed to run Docker commands without needing `sudo` every time.
- `usermod` = modify a user account.
- `-aG docker` = **a**ppend the user to the **G**roup named `docker` (without removing them from other groups).

```bash
newgrp docker
```
**What it does:** Refreshes/reloads your group membership in the current terminal session immediately, instead of requiring you to log out and log back in.

Now `docker ps` will work without errors.

### 6. Check versions of everything installed
```bash
docker --version
kind --version
kubectl version
```
- `docker --version` → shows the installed Docker version.
- `kind --version` → shows the installed KIND version.
- `kubectl version` → shows the installed kubectl (the "kube-control" tool used to give commands to any Kubernetes cluster) version.

## Part B: Writing the KIND cluster config file (YAML)

### 1. Make a folder and go into it
```bash
mkdir kind-cluster
cd kind-cluster
```
- `mkdir kind-cluster` → creates ("make directory") a new folder called `kind-cluster`.
- `cd kind-cluster` → moves your terminal into that folder.

### 2. Create the config file
```bash
vim kind-config.yaml
```
**What it does:** Opens `vim` to create/edit a file named `kind-config.yaml`. This is a **YAML file** — the format Kubernetes uses for almost all its configuration. YAML is just `key: value` pairs, lists, and nested objects (no special coding knowledge needed — like writing a structured checklist).

Example content typed into the file:
```yaml
kind: Cluster
apiVersion: kind.x-k8s.io/v1alpha4
nodes:
  - role: control-plane
    image: kindest/node:v1.31.0
  - role: worker
    image: kindest/node:v1.31.0
  - role: worker
    image: kindest/node:v1.31.0
  - role: worker
    image: kindest/node:v1.31.0
    extraPortMappings:
      - containerPort: 80
        hostPort: 80
        protocol: TCP
      - containerPort: 443
        hostPort: 443
        protocol: TCP
```
**Explanation, line by line, in plain English:**
- `kind: Cluster` → tells the tool "this YAML file describes a Cluster" (this is KIND's own config format, unrelated to the "KIND" tool name coincidence).
- `apiVersion: kind.x-k8s.io/v1alpha4` → which version of KIND's config format you're using (found on KIND's official docs/GitHub page).
- `nodes:` → a **list** of the machines (nodes) you want in your cluster.
  - `role: control-plane` → this node will be the **master/head node** — the "headquarters" that manages everything but doesn't run your actual app containers.
  - `role: worker` → these nodes actually run your application containers (Pods). Here 3 worker nodes are listed → total 4 nodes (1 master + 3 workers).
  - `image: kindest/node:v1.31.0` → since KIND runs Kubernetes *inside* Docker containers, each "node" is really a Docker container built from this specific image, running Kubernetes version 1.31.0.
- `extraPortMappings` → Because your whole cluster lives *inside* a Docker container (which itself is inside your EC2 instance), you need to **map ports** so traffic can reach it from outside. This says: "whatever hits port 80 (HTTP) or port 443 (HTTPS) on the actual host machine, forward it into port 80/443 inside this container." `protocol: TCP` specifies the network protocol used (TCP, the reliable connection-based protocol used for regular web traffic).

### 3. Save and exit vim
```
:wq
```
**What it does:** In vim, `:wq` means **w**rite (save) the file and **q**uit the editor.

## Part C: Creating the actual cluster

### 1. Create the cluster from your config file
```bash
kind create cluster --config kind-config.yaml --name tws-cluster
```
- `kind create cluster` → the core command telling KIND "build me a new Kubernetes cluster."
- `--config kind-config.yaml` → use the settings from this YAML file (our 4-node setup) instead of KIND's plain default (which is just 1 node).
- `--name tws-cluster` → give this cluster a custom name, `tws-cluster`, so you can identify/manage it later (useful if you create multiple clusters).

When you run this, KIND will:
1. Download the node image if not already present.
2. Prepare the nodes (containers).
3. Write the cluster's kubeconfig.
4. Start the control plane (API server, scheduler, controller-manager, etcd).
5. Install a default storage class.
6. Join the worker nodes to the cluster.
7. Print: **"You can now use your cluster."**

### 2. Check cluster info
```bash
kubectl cluster-info --context kind-tws-cluster
```
- `kubectl cluster-info` → asks the cluster "tell me your basic info" (where the control plane is running, DNS location, etc.).
- `--context kind-tws-cluster` → tells kubectl **which** cluster to talk to (your laptop/server can be configured to know about many clusters at once; `--context` picks the right one — KIND automatically names the context `kind-<cluster-name>`).

### 3. List all nodes in the cluster
```bash
kubectl get nodes
```
**What it does:** Asks the API server (via kubectl) to list every node in the cluster, its status (Ready/NotReady), and its role (control-plane or worker). This confirms your 1 master + 3 worker setup is actually running.
